# wb-dmx-fixtures

Сервис для контроллера Wiren Board, который превращает профили приборов из
[Open Fixture Library](https://open-fixture-library.org) (OFL, лицензия MIT) в MQTT-устройства
со «смысловыми» контролами (диммер, цвет, pan/tilt, режимы строба, колёса гобо) и пишет
получившиеся DMX-каналы в шлюз WB-MGU по Modbus TCP (регистры 0..511 — каналы вселенной,
1000 — blackout). Карта регистров шлюза описана в [`docs/dmx_plan.md`](../../docs/dmx_plan.md).

Без этого сервиса шлюз можно использовать через шаблон wb-mqtt-serial
(`templates/config-wb-mgu-dmx.json`) — но там каждый канал это просто ползунок 0..255.

## Как подключить приборы

Пример: 12 одинаковых паров, 6 голов и 2 стробоскопа.

1. Найти свои модели на open-fixture-library.org (поиск по производителю и названию).
2. В веб-интерфейсе контроллера открыть «Настройки → Конфигурационные файлы →
   DMX fixtures (WB-MGU gateway)», указать адрес шлюза.
3. В «Модели приборов» вставить ссылки на страницы трёх моделей, например
   `https://open-fixture-library.org/cameo/q-spot-40-rgbw`, и нажать «Сохранить».
   Сервис перезапустится, скачает недостающие профили и перестроит форму.
4. Обновить страницу. В «Приборах» добавить по записи на модель: выбрать модель и режим DMX
   (тот же, что выставлен на приборе), указать идентификатор (`par`), название и количество (12).
   Стартовый адрес `0` ставит приборы сразу после предыдущей записи; номер, отличный от нуля,
   задаёт его явно. После смены модели в записи режим сбрасывается — его нужно выбрать заново.
5. Сохранить. В «Устройствах» появятся `dmx_par1` … `dmx_par12`, групповое `dmx_par`
   («Par (все)») и остальные приборы. Карта адресов — в контроле «DMX-адреса» устройства
   `wb_dmx_fixtures`, по ней выставляются адреса на самих приборах.

Профиль, которого нет в OFL, собирается в онлайн-редакторе OFL
(open-fixture-library.org/fixture-editor) или пишется вручную в том же формате. Дальше —
либо положить файл в `/mnt/data/wb-dmx-fixtures/library/custom/<имя>.json` и выполнить
`wb-dmx-fixtures update-schema`, либо вставить в «Модели приборов» https-ссылку на JSON:
такой профиль сохраняется как `custom/<имя файла>`.

## Что появляется в MQTT

* `/devices/wb_dmx_fixtures` — служебное устройство: состояние, адрес шлюза, число приборов,
  карта DMX-адресов, состояние библиотеки моделей (сколько профилей, что скачано, ошибки
  скачивания) и кнопка `blackout` (гасит все контролы и шлёт blackout в шлюз).
* `/devices/dmx_<id>` — по устройству на прибор. Если в записи `count` больше 1, приборы
  получают id `<id>1` … `<id>N` (`<id>_1` …, если id сам кончается цифрой).
* `/devices/dmx_<id>` для записи с `count` > 1 — групповое устройство с теми же контролами,
  что у одного прибора. Запись в контрол группы уходит во все её приборы; запись в
  отдельный прибор меняет только его. Группа показывает последнее значение, отправленное ей.
* В `meta/error` устройств ставится `w`, пока шлюз недоступен.

Изменения нескольких соседних по адресам приборов (типично — групповая команда) уходят
в шлюз одним блоком FC16, а не запросом на каждый прибор.

### Карта контролов

Профиль OFL разворачивается в список каналов выбранного режима, каждый канал — в контрол:

| Канал OFL | Контрол WB | Как пишется в DMX |
|---|---|---|
| Одна capability на весь диапазон (Intensity, Focus, Speed …) | `range` 0..255 с именем канала (`dimmer`, `focus` …) | значение в канал; fine-канал, если он есть в режиме, получает младший байт `0` |
| `Pan`, `Tilt` с fine-каналом | `range` 0..65535 | старший байт в грубый канал, младший — в fine |
| `Red`, `Green`, `Blue` одного пикселя | один `rgb`-контрол `color` (`color_<pixel>` для матриц) | три канала |
| Другие `ColorIntensity` (`White`, `Amber`, `UV` …) | `range` 0..255 | значение в канал |
| Канал с несколькими capability (строб, колесо цветов/гобо, макросы, программы) | `<name>_mode` — `value` с `enum`, в веб-интерфейсе выпадающий список с подписями из OFL; плюс `<name>` — `range` 0..100 %, если хотя бы одна capability непрерывна (скорость, угол, температура) | начало диапазона выбранной capability; для непрерывной — точка внутри диапазона по уровню в % |
| `NoFunction` на весь канал | контрола нет | значение по умолчанию из профиля |

Имена контролов — имя канала OFL в snake_case. Порядок в карточке: диммер, цвет, остальные
цветовые каналы, pan, tilt, дальше по порядку каналов режима; последним — текстовый `profile`
(«Q-Spot 40 RGBW · 9-channel · DMX 1–9», у группы — «… · 12 × 9 · DMX 1–108»). Подписи
режимов переводятся на русский по словарю частых слов (`Open`, `Strobe`, `Slot` …),
незнакомые остаются как в OFL.

Что получится для конкретного профиля, можно посмотреть без запуска сервиса:

```bash
wb-dmx-fixtures show stairville/mh-x50 --mode 14ch
```

## Конфиг

`/etc/wb-dmx-fixtures.conf`, обычно редактируется формой:

```json
{
  "gateway": {"host": "192.168.13.172", "port": 502, "unit_id": 1, "write_interval_ms": 25},
  "models": ["https://open-fixture-library.org/eurolite/led-par-56-tcl"],
  "fixtures": [
    {"id": "par1", "name": "Par 1", "fixture": "cameo/q-spot-40-rgbw", "mode": "9-channel", "address": 1},
    {"id": "head1", "name": "Moving head 1", "fixture": "stairville/mh-x50", "mode": "14ch", "address": 20},
    {"id": "wash", "name": "Wash", "fixture": "eurolite/led-par-56-tcl", "mode": "5-channel", "count": 6, "address": 0}
  ]
}
```

Здесь `wash1` … `wash6` займут каналы 34–63, сразу после `head1`.

* `models` — ссылки на страницы open-fixture-library.org, ключи `производитель/прибор`,
  ссылки на файлы репозитория OFL на GitHub или https-ссылки на любой JSON в формате OFL.
  Недостающие модели скачиваются при старте сервиса; уже скачанные не перекачиваются.
  Удаление строки из `models` профиль из библиотеки не удаляет.
* `count` (по умолчанию 1) и `address` (по умолчанию 0 — «сразу после предыдущей записи»)
  необязательны, конфиги без них остаются рабочими.
* `write_interval_ms` — пауза перед записью после изменения, чтобы поток значений от ползунка
  схлопнулся в одну запись.

Ошибки конфига (профиль не в библиотеке, нет такого режима, пересечение адресов, выход за
512 каналов, повтор идентификатора, в том числе между прибором и группой) — сервис завершается
с кодом 6, текст ошибки виден в `journalctl -u wb-dmx-fixtures` и в состоянии устройства
`wb_dmx_fixtures`. systemd такой выход не перезапускает (`RestartPreventExitStatus=6`);
после исправления конфига через форму сервис стартует сам. Если прибор ссылается на модель,
которую не удалось скачать из-за сети, сервис завершается с кодом 1 и systemd повторит попытку.

## Установка

Пакет собирается стандартным для WB способом (архитектуронезависимый, Python):

```bash
cd controller/wb-dmx-fixtures
wbdev ndeb
```

`wbdev` нужен Docker; на машине без него пакет можно собрать в любом Debian/Ubuntu с
`debhelper`, `dh-python`, `python3-setuptools`, `python3-pytest` и `python3-wb-common`
командой `dpkg-buildpackage -us -uc -b`. Установка на контроллере:

```bash
apt install ./wb-dmx-fixtures_*.deb
```

Пакет ставит юнит `wb-dmx-fixtures.service`, пустой конфиг `/etc/wb-dmx-fixtures.conf`
(адрес шлюза не задан — сервис запускается, но пишет в состоянии, что шлюз не настроен)
и генерирует схему формы `/var/lib/wb-mqtt-confed/schemas/wb-dmx-fixtures.schema.json`.
На wb-2609 wb-mqtt-confed читает схемы только из `/usr/share/wb-mqtt-confed/schemas` и
`/var/lib/wb-mqtt-confed/schemas`, каталог `/etc/wb-mqtt-confed/schemas` он не смотрит.
Библиотека профилей живёт в `/mnt/data/wb-dmx-fixtures/library/<manufacturer>/<fixture>.json`
и переживает обновление прошивки.

Запуск из исходников без пакета (как на прототипе): скопировать каталог на контроллер,
в юните задать `Environment=PYTHONPATH=<каталог>` и `ExecStart=/usr/bin/python3 <каталог>/bin/wb-dmx-fixtures`.

## Командная строка

```bash
wb-dmx-fixtures import cameo/q-spot-40-rgbw https://open-fixture-library.org/stairville/mh-x50
wb-dmx-fixtures update-schema
wb-dmx-fixtures show cameo/q-spot-40-rgbw --mode 9-channel
```

`import` скачивает профили (перезаписывая уже скачанные) и перегенерирует схему формы.
Контроллеру нужен доступ к raw.githubusercontent.com.

Не поддерживаются матричные профили с блоками `matrixChannels` в режиме (`insert`); такой
профиль отвергается при скачивании. Пиксели, перечисленные в режиме явно
(`Red 1`, `Green 1` …), работают.

## Ограничения формы

Форма — штатный редактор confed, он строит статическую форму по JSON Schema. Поэтому:

* модель появляется в списке только после сохранения и перезагрузки страницы;
* связь «модель → её режимы» выражена отдельной веткой `oneOf` на каждую модель библиотеки,
  и форма растёт вместе с библиотекой — держать в ней сотни моделей не стоит;
* поиска по OFL в форме нет, ссылку на модель берут с сайта OFL.

## Разработка

```bash
cd controller/wb-dmx-fixtures
python3 -m pytest tests -q                   # на машине с pytest
uv run --with pytest --with jsonschema python -m pytest tests -q -o addopts=""   # без установленного pytest
```

Тесты не требуют `wb_common` и MQTT: модули `ofl`, `mapping`, `config`, `library` чистые,
сервис импортируется только командой запуска. Проверка конфига по схеме формы использует
`jsonschema` и пропускается, если его нет. Эталонные профили для тестов лежат в `tests/ofl/`.
