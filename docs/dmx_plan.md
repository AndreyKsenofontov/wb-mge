# DMX512-шлюз на WB-MGU (ветка `feature/dmx-gateway`)

Цель: превратить RS-485 порт WB-MGU в выход DMX512, который получает данные по сети
(Art-Net, sACN/E1.31, Modbus TCP) и управляется через штатный веб-интерфейс wb-mge.

## Куда встраивается

В прошивке у каждого порта есть транспортный режим `pm_mode_t`
(`main/bridge/port_manager.h`): `disabled`, `tcp_bridge`, `passive`, `repeater`.
DMX добавляется пятым режимом `PM_MODE_DMX` / `"dmx"`. Образец для копирования —
`repeater`: у него свои init/deinit, статистика в `/info` и своя страница во фронтенде.

Точки изменения:

| Файл | Что меняется |
|---|---|
| `main/bridge/port_manager.{h,c}` | `PM_MODE_DMX`, ветки в `port_init_mode` / deinit / `get_port_serial_desc` / проверке изменения настроек |
| `main/setting_items.h`, `setting_validators.c` | `PORT_MODE_DMX_STR`, валидатор, новые ключи NVS (см. ниже) |
| `main/settings_manager.c` | маппинг новых настроек |
| `main/bridge/dmx_output.{h,c}` (новый) | генерация кадров DMX на UART |
| `main/bridge/dmx_artnet.{h,c}`, `dmx_sacn.{h,c}` (новые) | UDP-приёмники, разбор пакетов |
| `main/bridge/dmx_modbus.{h,c}` (новый) | карта регистров каналов для Modbus TCP |
| `main/info_handlers.c` | блок `dmx` в `GET /info` |
| `main/frontend/src/views/Dmx.vue` (новый), `RsStatus.vue`, `Sidebar.vue`, `i18n/messages.ts` | выбор режима, настройки, монитор каналов |
| `unittests/dmx_*` | парсеры Art-Net/sACN, буфер, политика потери сигнала |

## Выход DMX (`dmx_output`)

- UART 250000 бод, 8N2. Драйвер — штатный IDF `uart`, без сторонних компонентов на первом этапе.
- **Режим `UART_MODE_UART`, а не `RS485_HALF_DUPLEX`.** В half-duplex RTS опускается после
  каждой посылки, и линия «плавает» во время MAB и между кадрами. DMX требует, чтобы передатчик
  держал линию всё время. Поэтому DE (GPIO15 на MGU) — обычный GPIO, всегда в 1, пока порт в режиме DMX.
- Кадр: BREAK (по умолчанию 176 мкс, допустимо ≥ 88) → MAB (по умолчанию 12 мкс, ≥ 8) → start code 0x00 → N слотов (по умолчанию 512).
  BREAK формируется через `uart_set_line_inverse(UART_SIGNAL_TXD_INV)` + `esp_rom_delay_us`,
  так длительности задаются точно. Запасной вариант — `uart_write_bytes_with_break`.
- Отдельная задача с высоким приоритетом, частота обновления настраивается (по умолчанию 40 Гц,
  максимум ~44 Гц при 512 каналах).
- Буфер 512 байт с двойной буферизацией: сетевые источники пишут в back-buffer, задача вывода
  под коротким мьютексом берёт снимок.
- Терминатор включён, подтяжка выключена (через TCA9535). Нужно уточнить по схеме, см. вопросы.

## Источники данных

- **Art-Net 4**: UDP 6454, `ArtDmx` (фильтр по Net/SubNet/Universe), ответ на `ArtPoll` (`ArtPollReply`),
  чтобы шлюз находили пульты и софт (QLC+, MagicQ, grandMA, Resolume).
- **sACN / E1.31**: UDP 5568, multicast `239.255.<hi>.<lo>` (IGMP join в lwIP), учёт приоритета источника
  и sequence number, unicast тоже принимаем.
- **Modbus TCP**: holding-регистры 0..511 = каналы 1..512 (младший байт), плюс служебные регистры
  (blackout, частота, состояние, активный источник). Для контроллера WB пишется шаблон wb-mqtt-serial,
  и DMX-приборы управляются из wb-rules и веб-интерфейса контроллера.
- Слияние источников: «последний писавший» с приоритетом sACN > Art-Net > Modbus (настраивается), HTP — позже.
- Потеря сигнала: по таймауту (по умолчанию 3 с) — `hold` (держать последнее), `blackout` или `scene` (сохранённая сцена).

## Настройки (NVS, на каждый порт)

`dmx_universe_N`, `dmx_sources_N` (битовая маска artnet/sacn/modbus), `dmx_channels_N` (24..512),
`dmx_refresh_hz_N`, `dmx_break_us_N`, `dmx_mab_us_N`, `dmx_loss_policy_N`, `dmx_loss_timeout_N`.

## Порт 2 / WBE2

**Вне рамок прототипа.** Прототип работает только на встроенном RS-485 (порт 1, GPIO14/12/15).
Режим `dmx` формально доступен и на порту 2 (так устроен `port_manager`), но на MGU порт 2 — это
шина WBE2 (TX=GPIO10, RX=GPIO4, RTS=GPIO13), и без модуля изолированного RS-485 там ничего нет.

## REST API этапа 1

- `POST /ports/N/mode` `{"mode":"dmx"}` — включить режим (сохраняется в NVS, как остальные режимы).
- `POST /settings` `{"rs485_1":{"dmx_slots":512,"dmx_refresh":40,"dmx_break":176,"dmx_mab":16}}` — параметры кадра;
  смена параметров перезапускает порт, как и для других режимов.
- `GET /ports/N/dmx` — `active`, `tx_disabled`, `slots`, `period_us`, `frames_sent`, `uptime_ms`, `values[512]`.
- `POST /ports/N/dmx` `{"start":1,"values":[255,0,128]}` и/или `{"blackout":true}` — запись каналов (тестовый паттерн).
- `GET /info` → блок `dmx.rs485_N` с той же статистикой.
- `tx_disabled` порта в режиме DMX держит DE в 0: кадры генерируются, но на шину не выдаются.

## Этап 2: Modbus TCP (`main/bridge/dmx_modbus.c`)

Порт в режиме `dmx` поднимает Modbus TCP сервер на своём `bridge_port_N` (502 для порта 1, 503 для порта 2) —
тот же TCP-порт, который в режиме `tcp_bridge` занимает шлюз, так что для контроллера это обычное Modbus TCP
устройство по адресу шлюза. Unit ID любой (255 — служебная карта самого шлюза, как в tcp_bridge).
Проверка коллизий портов в `POST /settings` учитывает `dmx` как локальный слушатель.

| Регистр (0-based) | Доступ | Значение |
|---|---|---|
| 0…511 | FC03/04 чтение, FC06/16 запись | каналы DMX 1…512, 0…255 (больше → exception 03) |
| 1000 | запись 1 | blackout — обнулить все каналы; читается как 0 |
| 1001 | RO | active |
| 1002 | RO | slots |
| 1003 | RO | частота кадров, Гц |
| 1004 / 1005 | RO | frames_sent, младшие / старшие 16 бит |
| 1006 | RO | tx_disabled |

Диапазон чтения не может пересекать границу блоков (0…511 и 1000…1006), иначе exception 02.
Запись в RO-регистры → exception 02. Проверка: `scripts/dmx_modbus_client.py`.

Проверено на плате 23.10.2026: FC16 на 11 каналов и FC06 читаются обратно и побайтно совпадают с потоком
на шине (`wave_decode.py`), исключения 02/03 отдаются по спецификации, статус-блок показывает 40 Гц и счётчик кадров.

## Этап 4: веб-интерфейс шлюза (`main/frontend/src/views/Dmx.vue`)

Страница «DMX» в группе инструментов: выбор порта, переключатель режима `dmx` (POST `/ports/N/mode`),
живая статистика из `/info`, форма таймингов кадра (`dmx_*` через `/settings`), 512 ползунков каналов
(показаны первые 32, остальные по кнопке), «Погасить всё» и «Видимые на 255» через `/ports/N/dmx`.
Вселенная перечитывается раз в 3 с, чтобы были видны записи по Modbus и с контроллера.
Режим `dmx` добавлен в подписи режима порта (Sidebar, RsStatus, глобальные сообщения) на пяти языках.
Тесты: `Dmx.integration.test.ts` (10 сценариев).

Брендинг по модели: для `mgu_v1` hostname и SSID точки доступа по умолчанию начинаются с `WB-MGU`
(`BASE_HOSTNAME` в `config.h`), `GET /hostname` дополнительно отдаёт `model` и `signature`, и страница
входа показывает модель в чипе, заголовок «MGU: шлюз DMX для Wiren Board» и ссылку на wiki WB-MGU.
Уже прошитое устройство хранит старый hostname в NVS — сменить можно в настройках.

## Этап 3: сетевые источники Art-Net и sACN (`main/bridge/dmx_net*.c`)

- `dmx_net_proto.c` — чистый разбор пакетов (хостовые тесты): Art-Net `ArtDmx`/`ArtPoll`, сборка `ArtPollReply`;
  E1.31 data-пакет (root/framing/DMP), multicast-группа universe.
- `dmx_net.c` — одна задача-приёмник на оба порта: UDP 6454 и 5568, `select()`, IGMP-членство на каждый
  настроенный universe sACN, ответ на `ArtPoll` (по одному на порт, BindIndex 1/2), приоритет источников sACN
  (следуем источнику с наибольшим приоритетом, таймаут 2,5 с, `stream terminated` освобождает universe).
  Принятые слоты пишутся через `dmx_output_set_channels`; Modbus TCP и страница работают параллельно
  («последний писавший»).
- Потеря сигнала: `dmx_loss` = `hold` | `blackout`, `dmx_loss_timeout` секунд.
- Настройки на порт (`rs485_N` в `/settings`): `dmx_artnet`, `dmx_artnet_universe` (15-битный port-address),
  `dmx_sacn`, `dmx_sacn_universe`, `dmx_loss`, `dmx_loss_timeout`. Смена перезапускает порт.
- `/info` → `dmx.rs485_N.artnet|sacn`: `enabled, universe, active, packets, fps, last_source` (+`priority` у sACN),
  `signal_lost`.
- Страница DMX: карточка «Сетевые источники» с галочками, universe, политикой потери и живой статистикой.
- Проверка с ПК: `scripts/dmx_net_send.py artnet <ip> <port-address>`, `… sacn multicast <universe>`, `… poll broadcast`.

## Шаблон wb-mqtt-serial для контроллера Wiren Board

`templates/config-wb-mgu-dmx.json.jinja` — исходник, `templates/config-wb-mgu-dmx.json` — отрендеренный
шаблон (все 512 каналов как `range` 0…255, включены первые 32, остальные `enabled: false` — включаются
в настройках устройства; Blackout — кнопка, статус — только чтение). Проверен валидатором навыка
`mqtt-serial-template` по схеме драйвера.

Установка на контроллер:
1. Скопировать JSON в `/etc/wb-mqtt-serial.conf.d/templates/config-wb-mgu-dmx.json`
   и перезапустить `wb-mqtt-serial` (или перезагрузить страницу настроек — драйвер перечитает шаблоны).
2. В настройках драйвера добавить порт типа **Modbus TCP** (`port_type: "modbus tcp"`, не «Serial over TCP»):
   адрес шлюза, порт 502 (= `bridge_port_1`).
3. На этом порту добавить устройство типа «WB-MGU DMX gateway», slave id любой (например 1).
4. В веб-интерфейсе контроллера появится устройство `wb_mgu_dmx_1` с каналами DMX 1…32 и кнопкой Blackout.

## Прошивка прототипа по USB

На плате v1.2 автозаход в загрузчик через DTR/RTS не работает: сброс (EN) проходит, но GPIO0 к моменту
снятия сброса остаётся высоким (З-2/З-3 ревью). OTA по HTTP прошивка отвергает, пока в eFuse нет
сигнатуры (`Device signature is empty, OTA not allowed`). Рабочая процедура:

1. `python scripts/usb_boot_hold.py COM5 120` — держит DTR так, что Q7 тянет GPIO0 вниз.
2. Пока скрипт держит линию, выключить и включить **питание платы** (USB не трогать). В консоли появится
   `boot:0x20 (DOWNLOAD_BOOT)` / `waiting for download`.
3. После завершения скрипта: `python -m esptool --chip esp32 -p COM5 -b 460800 --before no-reset
   --after hard-reset write-flash --flash-mode dio --flash-size 4MB --flash-freq 40m 0x90000 <app.bin>`.

На пустой флеш (первая прошивка) ROM сам остаётся в download-режиме, и шаги 1–2 не нужны.

## Результат этапа 1 на железе (23.10.2026, плата WB-MGU v1.2, Rigol DHO804)

Прошивка `mgu_v1` с режимом `dmx` залита по USB-C (флеш платы была пустой). Порт 1 в режиме `dmx`,
512 слотов, 40 Гц. Измерено на клеммах A/B (`scripts/scope.py`, `scripts/wave_decode.py`):

| Параметр | Задано | Измерено |
|---|---|---|
| BREAK | 176 мкс | 178,6 мкс |
| MAB | 16 мкс | 25–29 мкс (накладные `uart_write_bytes`; норма ≥ 12 мкс) |
| Период кадра | 25 000 мкс | 25,0 мс, счётчик кадров 40,0 Гц |
| Уровни A / B | — | 0,74–4,19 В / 0,48–4,31 В, терминатор 120 Ом включён |
| Фронты | — | ~0,36 мкс нарастание, ~0,65 мкс спад |
| Данные | 00 FF 80 40 20 10 08 04 02 01 AA 55 00… | совпадают побайтно |

Скриншоты: `docs/images/dmx_break_mab.png`, `dmx_frame_period.png`, `dmx_bit_edges.png`.

Замечания:
- Вселенная хранится в ОЗУ: после перезагрузки порт поднимается в режиме `dmx` с нулями. Для прототипа нормально;
  при появлении сетевых источников это и будет штатным поведением (blackout до первого пакета).
- `quad_psram: VDDSDIO is not 3.3V` при загрузке — подтверждение замечания З-1 из ревью схемы; PSRAM не стартует,
  прошивка работает без неё.
- Консоль USB-C: открытие порта терминалом с переключением DTR/RTS сбрасывает плату; открывать с уже
  установленными DTR и RTS.

## Этапы

1. **Выход DMX**: режим `dmx`, `dmx_output`, тестовый паттерн из веб-интерфейса, проверка таймингов осциллографом и DMX-тестером.
2. **Art-Net + sACN**: приёмники, потеря сигнала, статистика в `/info`.
3. **Modbus TCP** + шаблон wb-mqtt-serial.
4. **Фронтенд**: страница DMX, монитор 512 каналов, ручные фейдеры.
5. Дальше, вне прототипа: второй universe через изолированный модуль WBE2, RDM (вероятно, через
   компонент `esp_dmx`), вход DMX, сцены.

Каждый этап собирается командой `make build-frontend unittests test-frontend build-idf-project`
(требование AGENTS.md) и проверяется на железе.

## Железо (по «WB-MGU v1.2(4layers) — design review», 19.10.2026)

- **Трансивер**: U5 TP8485E-SR от +5V. DI ← IO14, **DE и /RE объединены ← IO15**, R7 10k на GND
  (в сбросе ESP32 передатчик выключен). RO → U2 SN74LVC1G08 → IO12. TVS SMAJ6.0CA + полифьюзы MF-NSMF012-2.
  Порт **не изолирован**.
  - По дистрибьюторам TP8485E — **250 кбит/с**, то есть DMX ровно на пределе паспорта, фронты со slew-limit.
    Обязательно смотреть осциллографом на длинном кабеле; при проблемах — изолированный порт через WBE2.
  - DE = 1 постоянно в режиме DMX → приёмник выключен (/RE = 1): вход DMX / RDM на этом порту требует
    переключать направление, как в half-duplex.
- **TCA9535 на MGU**: P00 — терминатор (фотореле O1 + 120R), P02 — смещение (2×560R), P04/P05 — LED Wi-Fi/Eth,
  P06 — VOUT, P07 — Status. P01/P03/P10–P14 не подключены. Терминатор и смещение независимы →
  в режиме DMX рекомендуем «терминатор вкл., смещение выкл.» (это штатные настройки порта, прошивка их не форсирует).
- **Светодиоды RX/TX** (LED1, двухцветный) висят прямо на линиях UART1 через 220R — в режиме DMX TX будет гореть постоянно.
- **WBE2**: PBD-12 — 3.3V, 5V, GND, OUT1–4, TX = IO10, RX = GPIO4, RTS = IO13. Для прототипа не используется.
- **PSRAM** ESP-PSRAM64H на CE = IO9 предусмотрена схемой; прошивка mgu_v1 загружается и без неё.
- Не про DMX, но важно: замечание З-1 ревью — IO12 (MTDI, strap VDD_SDIO) удерживается в «1» выходом U2 при сбросе.
